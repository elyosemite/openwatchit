# Contributing to OpenWatchIt

OpenWatchIt is in its conception phase. There is no code to review, no PRs to open, and no issues to triage yet. This document explains what meaningful contribution looks like right now.

---

## The most valuable thing you can do today

**Answer the open questions in [GitHub Discussions](https://github.com/elyosemite/openwatchit/discussions).**

Each discussion thread corresponds to a real design decision. Your answers — especially the ones that contradict our assumptions — will directly shape what gets built, in what order, and whether this project moves forward at all.

You don't need to answer all ten. One detailed, honest answer from someone living the problem is worth more than ten generic ones.

---

## Other ways to contribute at this stage

**Share it with someone who has strong opinions.**
The SRE who manages your observability stack. The platform engineer who built the internal tooling. The DevOps lead who onboarded the last three engineers. They are the people whose feedback will make or break the design.

**Open a new discussion.**
If you have a use case, a constraint, or a question that isn't covered by the existing threads, open a new one. The RFC is not exhaustive. There are blind spots we don't know about yet.

**Push back publicly.**
If something in the proposal seems wrong, overly optimistic, or already solved by an existing tool — say so. A well-argued objection in a discussion thread is one of the best contributions this project can receive right now.

---

## Signaling intent for future contributions

If you'd like to contribute code when development starts, the best thing to do now is:

1. **Star the repository** — it helps us gauge interest and identify early adopters.
2. **Comment in the discussion thread** closest to the area you'd work on (OWL parser, a specific vendor plugin, the CLI, the UI).
3. **Watch the repository** — development milestones will be announced here first.

We are not collecting email addresses or running a waitlist. GitHub is the only coordination channel.

---

## What we are not looking for right now

- Code submissions — there is no codebase yet.
- Plugin implementations — the plugin contract (gRPC schema) is not finalized.
- UI mockups or designs — the core query semantics come first.
- Feature requests beyond the RFC scope — get the fundamentals right first.

None of this is meant to discourage initiative. It's meant to save your time. When the project is ready for code, this document will change significantly.

---

## Code of Conduct

Be direct. Be specific. Assume good faith. Disagree on ideas, not on people.

There is no formal CoC document at this stage. If that needs to change, it will.
